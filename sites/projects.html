Small machines, real operating constraints.

This is intentionally concrete: hardware, services, exposure model and what each system is for.

load context: private-infrastructure-lab render projects: ready
primary node

raspberry-pi-4 / mixed-services

Hosts practical services that are useful enough to keep alive and messy enough to teach real operations work.

  • Surveillance-Cam-Controller, FTP/Samba, Paperless-ngx and Portainer
  • Node-RED, Grafana and InfluxDB 1.8
  • private torrent/*arr media stack stays private; only the isolation, update and monitoring logic is documented publicly
automation node

raspberry-pi-3 / watering-control

Automated watering setup using sensor input and condition-based control actions.

  • DHT22 temperature/humidity readings
  • hygrometer-based soil moisture checks
  • automation logic tested as a physical feedback loop, not just a script demo
edge node

pi-zero-w / public-camera

Lightweight surveillance camera project used as a public networking and uptime exercise.

  • small-device constraints: storage, thermals, network stability and recovery
  • useful for practicing external access, monitoring and service checks
operating rule

public-docs / private-boundaries

Public pages explain the architecture and operational thinking. Sensitive service details, private endpoints and personal media paths stay out of the public surface.
